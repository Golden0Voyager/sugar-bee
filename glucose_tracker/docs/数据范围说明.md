## 技术实现

### SQL 查询逻辑

**代码位置**: `app.py` 第 470-473 行

```python
c.execute("""
    SELECT value, type, timestamp FROM records
    WHERE user_id = ?
    AND value > 0
    AND is_predicted = 0
    AND timestamp > datetime('now', ? || ' days')  # 关键条件
    AND type NOT IN ('跑步', '运动', '血压')
    ORDER BY timestamp DESC
""", (user_id, f'-{days}',))
```

### 时间计算规则

1. **参数传入**: `days = 7`（默认）
2. **SQL 条件**: `timestamp > datetime('now', '-7 days')`
3. **含义**: 获取从7天前到现在的所有数据

### 实际示例

假设当前时间是：`2026-01-06 15:30:00`

```
计算7天前：
datetime('now', '-7 days') = 2025-12-30 15:30:00

SQL条件：
timestamp > 2025-12-30 15:30:00

包含的数据：
✓ 2025-12-30 15:30:01 之后的所有数据
✓ 2025-12-31 00:00:00 ~ 23:59:59（完整一天）
✓ 2026-01-01 ~ 2026-01-05（完整5天）
✓ 2026-01-06 00:00:00 ~ 15:30:00（当天到现在）

总计：约7天的数据，包含当天
```

## 常见问题

### Q1: 为什么是"近7天"而不是"最近7天"？
**A**: "近7天"更准确，因为：
- 包含当天的部分数据（到当前时刻）
- 不是完整的7个自然日
- 实际时间范围是浮动的（随查询时间变化）

### Q2: 数据会实时更新吗？
**A**:
- 数据库查询是实时的
- 但分析报告需要手动或自动触发生成
- 生成后的分析结果会保存，不会自动更新

### Q3: 如何获取更长时间范围的分析？
**A**:
```javascript
// 前端修改
analyzeHealth(14);  // 14天分析
analyzeHealth(30);  // 30天分析
```

### Q4: 当天没有数据会影响分析吗？
**A**:
- 不会报错
- 分析会基于可用的数据
- 如果7天内完全没有数据，会提示数据不足

### Q5: 时间范围是否包含边界？
**A**:
- 使用 `>` 不包含边界
- `timestamp > datetime('now', '-7 days')`
- 7天前的那一刻不包含，之后的所有数据都包含
