## 1. 用户自定义槽位（预测 + 前端显示）

**提出**：2026-10-31

**现状**：系统内置 7 个固定槽位（`settings.DAILY_ROUTINE`）：07:15 空腹、08:45 运动后、11:00 早餐后2小时、14:30 午餐后2小时、17:30 晚饭前、20:00 晚餐后2小时、22:00 睡前。这些槽位散落在多处硬编码：

- `glucose_parser.py`：自然语言录入「空腹/早餐后2小时」等词时映射到默认时刻——**即使用户实际测量时间是别的点，也会被改写成槽位时刻**（2026-10-31 核实：生产库 294 条空腹记录 290 条时间戳是 07:15，真实测量时刻丢失）；
- `services/prediction_service.py`：AI 预测硬编码写 `07:15`；
- `services/dashboard_service.py` / `routes/api_dashboard.py` / `routes/api_prediction.py`：前端「每日 routine」卡片、预测的 `type_patterns` 匹配。

**需求**：槽位的**数量、名称、时刻**全部可由用户自定义（如有人要加「午餐前」「睡前胰岛素」、或把早餐后2小时改成 1.5 小时）。

**设计要点（立项时考虑）**：

- 存 `user_profiles`（JSON 列）还是独立表——槽位数量少（≤10）、按用户隔离，JSON 列起步即可；
- 预测任务按用户的槽位表生成预测目标，不再硬编码 07:15；
- 自然语言录入仍保留「关键词 → 槽位默认时刻」的兜底，但**应优先保留用户口述的真实时刻**（修掉 290/294 空腹挤在 07:15 的问题）；
- 前端设置页增加槽位编辑器（增删改：名称 + 时间 + 是否参与预测）；
- 旧数据兼容：历史记录的中文 type 标签（空腹/早餐后2小时…）仍是查询口径，自定义名称别破坏现有 type 体系（可映射到 `record_time`/槽位 id）。

**关联**：data-quality 核实记录见 2026-10-31 会话（119 组重复中 86 组是空腹槽位冲突造成的假重复）。
