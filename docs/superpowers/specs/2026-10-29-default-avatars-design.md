# 默认头像库设计

日期：2026-10-29
状态：用户已确认界面与技术方案

## 背景

当前头像功能只支持用户上传 PNG/JPEG、裁剪并保存到 `app_users.avatar`。没有头像时，页面显示通用人物图标。用户希望增加一组可直接选择的默认头像，并保证选择结果在刷新、重新登录和换设备后仍然保留。

## 已确认需求

- 提供 18 个默认头像：9 个彩色人物插画 + 9 个可爱动物。
- 默认头像与现有的“上传自己的图片”共存。
- 选择界面分为“人物”和“动物”两组，采用已确认的九宫格布局；选择后预览，点击保存才持久化。
- 从未选择过头像的用户按用户 ID 固定分配一个默认头像，不使用随机分配。
- 主动选择默认头像后写入数据库；已有上传头像不得被自动分配覆盖。
- 使用本地 SVG，不依赖第三方头像 URL。

## 非目标

- 不新增头像数据库字段或数据表。
- 不批量改写老用户的 `avatar` 值。
- 不删除用户历史上传的图片文件。
- 不增加后台头像管理页面，本轮头像清单由代码固定。
- 不改变现有上传、裁剪和登录流程。

## 方案概述

采用“本地 SVG + 按用户 ID 固定回退”：

1. 18 个 SVG 随项目发布，所有设备显示一致，文件小且加载快。
2. `avatar` 为空时，界面根据用户 ID 计算固定的默认文件名。该回退不写数据库，但结果始终一致。
3. 用户主动选择默认头像时，把对应的 `defaults/<name>.svg` 写入现有 `app_users.avatar`。
4. 用户上传头像仍按原流程写入文件和 `app_users.avatar`；只有用户主动更换时才覆盖这个字段。

## 头像文件与清单

目录：`static/avatars/defaults/`

- `person_01.svg` 至 `person_09.svg`：彩色人物插画。
- `animal_01.svg` 至 `animal_09.svg`：可爱动物，包含蜜蜂、虎、兔、熊、熊猫、考拉、狐狸、企鹅、猫头鹰。

`.gitignore` 继续忽略用户上传的 `static/avatars/` 内容，但为 `static/avatars/defaults/` 及其 SVG 文件增加例外；`.dockerignore` 同步增加例外，确保默认头像既进入版本控制，也不会在 Docker 构建上下文中被排除。

新增一个小型头像工具模块作为唯一清单来源，负责：

- 按固定顺序返回 18 个头像的标识、文件名、分组和展示名称。
- `default_avatar_for_user(user_id)`：使用用户 ID 对 18 取模，稳定返回一个默认文件名。
- `is_default_avatar(value)`：只接受清单内的 `defaults/person_XX.svg` 或 `defaults/animal_XX.svg`，拒绝其他路径和陌生文件名。

## 数据流与持久化

### 未设置头像

`UserManager.get_user_config(user_id)` 在数据库 `avatar` 为空时返回 `default_avatar_for_user(user_id)`。现有首页模板继续使用 `/static/avatars/{{ stats.user.avatar }}`，因此小头像和下拉菜单大头像使用同一结果，不需要各写一套分配逻辑。

数据库中的空值保持不变；固定算法保证同一用户每次看到相同头像。

### 主动选择默认头像

新增 `POST /select_avatar`，要求登录：

请求：

```json
{"avatar": "defaults/person_01.svg"}
```

处理：

1. 从 session 获取当前用户，不信任请求里的用户 ID。
2. 用头像工具模块校验值必须属于 18 个默认项。
3. 更新 `app_users.avatar` 并提交事务。
4. 返回标准成功响应，包含 `avatar` 和 `/static/avatars/...` 形式的 `avatar_url`。

响应数据：

```json
{
  "avatar": "defaults/person_01.svg",
  "avatar_url": "/static/avatars/defaults/person_01.svg"
}
```

非法输入返回 400，不修改数据库；未登录沿用现有 401/重定向行为；数据库异常沿用现有 500 错误包装。

### 上传自己的图片

保留现有 `/upload_avatar`、Cropper.js 裁剪和文件保存流程。上传成功后刷新页面，显示用户图片；之后选择默认头像也可以替换数据库中的上传文件名。历史文件不删除，避免引入额外的文件清理风险。

## 界面行为

在现有 `avatarModal` 上半部分加入：

- “默认头像 · 人物”9 个圆形按钮。
- “默认头像 · 动物”9 个圆形按钮。
- 当前选择有清晰描边和选中状态，并显示预览。
- “保存所选头像”在未选择时禁用，选择后启用。
- 上传入口保留；进入上传裁剪后，默认头像保存按钮不干扰原上传保存按钮。

保存默认头像成功后关闭弹窗并刷新页面，使导航栏和用户信息卡同时更新。保存失败保留弹窗和当前选择，显示错误提示，不做本地假成功。

小屏幕下使用可换行网格，保证 18 个头像可滚动访问，不强制横向滚动。

## 安全与兼容性

- 默认头像保存接口只接受白名单文件名，不接受任意路径，避免路径穿越和伪造站内 URL。
- 所有更新只作用于当前登录用户。
- 已上传头像非空时不执行自动分配，老用户显示不变。
- SQLite 与 PostgreSQL 复用同一 `UPDATE app_users ...` 路径，无方言差异和迁移。
- 默认文件进入版本控制，用户上传文件仍按原规则忽略和持久化。

### 自动化测试

- 清单恰好 18 项、文件名唯一，人物和动物各 9 项，所有 SVG 文件存在。
- 同一用户 ID 多次分配结果一致，不同 ID 的取模结果符合清单顺序。
- 空头像用户获得固定默认值，已有上传头像不被覆盖。
- `/select_avatar` 成功后当前用户的 `avatar` 持久化，响应 URL 正确。
- 陌生文件名、绝对路径、`..`、空值和非字符串返回 400，数据库不变。
- 未登录不能保存，不能替其他用户修改。
- 现有上传头像测试继续通过。
- 模板包含两组各 9 个选择项，并复用统一头像清单。

### 页面验收

1. 未设置头像的用户看到按 ID 固定的默认头像，刷新后不变。

3. 保存默认头像后刷新、退出再登录，仍显示所选头像。
4. 上传自定义图片后显示上传图；再选默认头像可换回。
5. 手机窄屏下 18 个头像可完整访问，无横向溢出。
6. 相关测试、全量 pytest 和修改文件的 ruff 检查通过。
